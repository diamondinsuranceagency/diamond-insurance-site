# Site-native reviews rollout

The public `/reviews` page keeps its previous testimonials. The new client form and owner dashboard require a configured PostgreSQL database and an owner-only credential. No automatic imports, client messages, or test rows are sent to production.

1. Use a dedicated PostgreSQL database or schema for the website's review data. Apply `db/migrations/001_site_reviews.sql` in the intended environment with a migration role that can create tables. Back up existing data and use a separate database for any preview/testing. Provide the runtime role just SELECT, INSERT and UPDATE on the two review tables, not schema administration.
2. In Vercel's environment settings, set server-only `DATABASE_URL` (provider's TLS-enabled or pooled Postgres connection URI), `REVIEWS_ADMIN_SECRET` (cryptographically random, for example generated locally with `openssl rand -hex 32` and saved in an approved password manager), and `REVIEWS_SITE_ORIGIN` (canonical HTTPS origin, production `https://diamondconsultingadvisory.com`). Set preview values only on an isolated preview and use a different credential. Never put a connection URI or owner secret into a public variable, a commit, or chat. If serving a second public hostname, redirect it to the canonical origin. On a non-preview production build, the route rejects writes from any other Origin.
3. Confirm the deployed `/reviews`, `/reviews/manage`, and `/reviews/leave` routes. Use the dashboard to create one invitation per consenting client and share its generated URL privately. Anyone with an unused link can redeem it; do not post invitations publicly. Links expire in 14 days and successful submission consumes them once, even with concurrent sends. Email link-preview requests don't consume invitations.
4. Keep moderation neutral across ratings: reject spam or sensitive information, not criticism. Manual entry is for verbatim client feedback with their permission; it is distinguished from client's direct submission. An archived review may be withdrawn from the public page without deleting its record. Rotating the owner credential signs out all existing owner sessions.
5. To test locally, apply the migration to a disposable loopback Postgres DB. Run Next with `DATABASE_URL`, `REVIEWS_SITE_ORIGIN` set to the loopback Next origin, and the throwaway `REVIEWS_ADMIN_SECRET`. With `REVIEWS_TEST_ORIGIN` and `REVIEWS_TEST_DATABASE_URL` pointing locally, run `node --test tests/reviews.integration.mjs`. The test intentionally writes synthetic data only to the disposable test database; reset that database after the run.
